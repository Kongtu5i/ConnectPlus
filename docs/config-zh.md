# ConnectPlus 配置文件中文对照（config.yml）

> 参考文档：`config.yml` 中的注释由插件在加载时自动重写为英文，手工修改会被覆盖；
> 本表供中文用户对照阅读。完整安装、玩家操作、账号关联与故障排查见[简体中文 README](../README.zh-CN.md)；配置项以当前插件生成的配置为准。

| 配置项 | 默认值 | 中文说明 |
|---|---|---|
| `mode` | `lobby` | 插件模式：`lobby`（默认，玩家进入内置大厅）或 `proxy`（关闭大厅，纯 ViaProxy 原行为） |
| `motd` | `§bConnectPlus Lobby` | 多人游戏服务器列表中的大厅描述，支持 `§` 颜色代码和换行；修改后重启代理。通配符直连及 `proxy` 模式沿用目标服描述 |
| `language` | `en` | 大厅 GUI 与聊天语言：`en`（英文，默认）、`zh`（中文）、`auto`（按每个玩家的客户端语言在可用语言包中自动选择）、或自定义语言包名（对应 `languages/<代码>.yml`，缺失行回退英文；`en.yml`/`zh.yml` 首次启动自动生成，可直接编辑） |
| `switchTimeoutSeconds` | `15` | 一次无缝热切换允许的最长时间（秒），超时把玩家送回大厅 |
| `maxConnectAttemptsPerMinute` | `30` | 每个玩家每分钟最大连接尝试次数（限流；0 = 不限流）。回大厅的兜底流程不受限流影响 |
| `blockLocalTargets` | `true` | 是否禁止玩家通过 GUI 地址输入连接到代理主机自身及回环/内网地址（默认开启）。**安全警告**：设为 `false` 后，任何玩家仅通过填写地址就能访问代理所在机器及其内网上的所有服务（其他 MC 服务器、管理面板、数据库等）——只有完全理解并接受该风险时才关闭 |
| `maxBookmarksPerPlayer` | `50` | 每个玩家最多保存的书签数量 |
| `allowAccountLogin` | `true` | 是否允许已认证连接登录微软账号和使用已保存账号。Java 连接要求 `proxy-online-mode=true` 且实际完成正版认证；基岩连接要求启用 Geyser 支持且桥接会话验证仍有效。在线模式和 Geyser 支持都关闭时，代理加载或启动会强制将此项改为 `false` 并保存 |
| `accountLoginAllowlist` | `[]` | 允许使用微软账号登录的玩家名白名单（空 = 所有人可用） |
| `transferPolicy` | `confirm` | 目标服务器发来 transfer 转移包时的处理：`confirm`（回大厅弹确认界面，默认）、`follow`（直接跟随转移）、`ignore`（忽略） |
| `backendDownPolicy` | `lobby` | 游戏中后端服务器断开时的处理：`lobby`（送回大厅，默认）或 `reconnect`（自动重连链） |
| `reconnectAttempts` | `3` | 自动重连尝试次数，耗尽后回大厅（0 = 不重试；仅 `backendDownPolicy=reconnect` 时生效） |
| `reconnectDelaySeconds` | `5` | 自动重连的基础等待秒数；首次恢复可立即开始，后续失败按基础间隔线性增加等待时间 |
| `kickPolicy` | `lobby` | 在目标服被踢时的处理：`lobby`（带踢出原因送回大厅，默认）或 `disconnect`（原样转发原版踢出界面） |
| `whitelist` | `false` | 启动时白名单开关；控制台 `on/off` 只影响本次运行，不写配置，重启恢复此值 |
| `blacklist` | `false` | 启动时黑名单开关；同样区分配置值和运行值，命中黑名单优先拒绝 |
| `debug` | `false` | 是否输出 ConnectPlus 开发诊断日志，值为 `true` 或 `false`；修改后重启。关闭时不输出报文转储、切服握手细节、GUI 和会话内部状态。开启时使用 `DEBUG` 级别；官方 ViaProxy 默认将这些内容写入 `logs/debug.log`，控制台和 `logs/latest.log` 保持日常输出。控制台的 `cp debug on\|off` 可在不重启、不改配置文件的情况下临时改变本项，仅本次运行有效，重启后恢复为本配置值 |
| `geyser-support.enabled` | `false` | 是否允许 ConnectPlus-GeyserBridge 扩展（外部 Geyser 扩展，桥接协议 v1）注册为可信基岩身份提供者。默认关闭：关闭时不产生基岩持久档案、也不提供基岩玩家的账号关联功能；已验证 Java 玩家完全不受影响。即使设为 `true`，也只有在已安装匹配的 Geyser 扩展、且其注册声明满足协议 v1 三项基础能力（verified-xuid、exact-channel-binding、targeted-disconnect）时，基岩功能才会开放；当前官方宿主桥接不声明 authenticated-duplicate-admission，同 XUID 重复连接由官方 Geyser 原生拒绝。提供者缺失、失效或版本不兼容时，基岩身份确认会被拒绝；开启此项不会自动修改 `allowAccountLogin` 的值，管理员禁用账号登录的语义保持不变 |

示例（双引号中的 `\n` 会显示为换行）：

```yaml
motd: "§a我的 ConnectPlus 大厅\n§b欢迎连接！"
debug: false
```

日常启动、连接结果和恢复信息归为 `INFO`；切服失败和警告归为 `WARN`，错误归为 `ERROR`，不受 `debug` 开关限制。需要定位问题时将 `plugins/ConnectPlus/config.yml` 中的 `debug` 改为 `true`，重启后查看 `logs/debug.log`；排查完成后改回 `false` 并重启。此选项控制 ConnectPlus 的诊断输出，ViaProxy 和 Geyser 自身沿用各自的日志设置。

目标版本未设置或在版本选择页选中 **Auto Detect (1.7+ servers)** 时，都先查询目标服务器状态并解析出具体协议版本，再建立连接。已有书签保存的自动选项同样生效，无需重新建立书签；手动指定版本沿用原有行为。自动探测结果在开启 `debug` 后写入诊断日志。

账号权限按原始客户端连接的认证身份判断。Java 玩家要求 `proxy-online-mode=true` 且该连接实际完成正版认证；仅打开开关、跳过认证或未取得可信身份都不能使用账号。基岩玩家要求 `geyser-support.enabled=true`，并且桥接证明仍匹配当前提供者、桥接会话和确切客户端连接；满足这些条件时，即使 Java 入口的在线模式关闭，也可登录、关联和恢复账号。桥接提供者停止或桥接会话关闭后，旧证明不能继续使用账号。

`allowAccountLogin=false` 会禁用两种版本的账号功能：玩家无法登录微软账号，也无法查看、恢复、使用或注销删除已保存的账号；切服、重连和服务器转移同样不会使用缓存账号。已加密保存的令牌和书签保留。正在进行的登录或关联即使后来完成，也会重新检查权限和租约。玩家自己的“离线连接”开关只控制是否向后端发送凭据，当前登录会保留。

在线模式和 Geyser 支持都关闭时，ConnectPlus 仍会在代理加载或启动时将自己的 `allowAccountLogin` 改为 `false` 并写回配置。配置文件无法写入时会记录错误，运行中的限制仍然生效。重新启用任一认证路径都不会自动打开账号登录；管理员需要明确将 `allowAccountLogin` 设为 `true`。

Java 连接完成认证且账号功能开启时，同一玩家通过不同游戏版本连接，会按 ViaProxy 登录验证后的原始 UUID 读取同一份账号和书签。旧版登录包缺少 UUID 不再导致重复登录；切服时使用其他后端账号也不会改变大厅数据的归属。账号恢复较慢时，已打开的大厅主界面会自动更新登录状态。

`geyser-support.enabled` 涉及基岩玩家身份桥接（Geyser-ViaProxy 形态的外部扩展，协议约定见 [桥接扩展项目仓库](https://github.com/Kongtu5i/ConnectPlus-GeryserBridge)）。关闭（默认）时桥接扩展无法注册，基岩连接不能升级为已验证基岩身份，因此不会创建或读取 `players/bedrock/` 档案，关联/解绑入口也不会出现；已验证 Java 玩家的档案、账号登录和书签行为与以前完全一致（已提交的绑定索引仍受保护，防止其被当作未绑定覆盖）。开启后若提供者未注册、已停用或版本不兼容，受影响的基岩连接同样拿不到受保护档案，也不会被当作 Java 身份静默落盘；普通连接功能仍可用。

基岩身份确认在后台进行，玩家可以先进入大厅。确认成功后，大厅自动取得档案使用权、加载对应档案，按账号权限配置恢复已保存账号，并更新已打开的主界面。确认尚未结束时，档案保存操作暂不执行，避免创建错误的临时档案。确认失败或超时仍可使用普通连接，但不能读取受保护档案、恢复账号或关联账号；断线后的旧结果和切服前旧大厅的回调不会更新当前会话。

未绑定的基岩玩家首次通过身份验证并取得档案使用权时，会立即创建 `plugins/ConnectPlus/players/bedrock/<XUID>.json`，不需要先登录 Java 账号或保存设置。关联成功后，绑定写入 `plugins/ConnectPlus/players/identity-links.json`，开始使用 `players/java/<JavaUUID>.json`，原基岩 JSON 按事务删除。已绑定玩家进入大厅时不再创建基岩 JSON；解绑后创建新的空白基岩档案。

## 大厅快捷物品

主菜单和书签详情里的服务器地址输入会自动将全角英文字母、数字及标点转为半角，例如 `１９２．１６８．１．１９４：２５５６５` 转为 `192.168.1.194:25565`。中文域名保留原文；转换后的地址仍按 `blockLocalTargets` 检查，不需要新增配置。

Java 与基岩玩家进入或返回大厅时，默认选中第 **5** 格快捷栏。箱子菜单打开期间收起菜单指南针和断开连接屏障，切换菜单页时保持收起；关闭箱子菜单后，在第 **5** 格恢复菜单指南针，第 **9** 格恢复断开连接屏障。选中物品后使用（右键）或挥动（左键／触屏点击）：指南针打开主菜单，屏障断开与代理的连接。基岩玩家需先关闭聊天框，再使用指南针；该入口不会强制关闭聊天框。

快捷物品位置固定，移动、丢弃或副手交换后会按菜单开关状态同步，菜单打开时不会重新发放。进入地址或书签名称等聊天输入时恢复两个物品，输入完成后返回菜单时再次收起。旧版教程书结束后使用指南针返回菜单。普通聊天不会打开箱子 GUI，关闭主菜单也不再发送“输入任意内容重新打开界面”的提示；已有命令和编辑输入继续可用。切入目标服务器前清理快捷物品，返回大厅按菜单开关状态同步，无需新增配置。

Java 与基岩的书签操作一致：左键点击书签打开详情，可重命名、修改地址／版本或删除；详情里的“连接服务器”按钮单独发起连接。书签列表不再显示右键编辑提示，打开详情不会发起连接。

书签详情使用六行箱子界面：第三行第 2 格显示书签信息，第 4、5、6 格分别为重命名、版本和地址，第 8 格为“连接服务器”；底行第 5 格返回，右下角为删除，删除仍需确认。

已验证的基岩连接使用统一的六行箱子和“ConnectPlus”标题，底行第 3 格的纸张显示当前页面名称，原有功能按钮位置保留。这样各页大小和标题一致，官方 Geyser 可以复用虚拟箱子，减少切页时关闭重开的交互。基岩玩家通过页面内的返回按钮回上级；点击关闭则退出整个 GUI 并恢复指南针，不自动重开父页面。关联 Java 档案的基岩玩家仍按原始基岩连接呈现；Java 客户端沿用原来的各页标题、行数和关闭返回行为，无需新增配置。

## 控制台命令

代理控制台接受 `cp` 与 `connectplus` 两个根命令（兼容 `/cp`、`/connectplus` 写法），两种插件模式下都可用。玩家命令仅保留 `/disconnect` 与别名 `/dc`：大厅中断开代理连接，切到目标服务器后返回大厅；连接、版本、书签、账号等操作全部在 GUI 中完成，目标服务器自身定义的命令原样转发不受影响。

大厅中给退出命令添加参数（如 `/dc extra`）会收到 CP 用法提示；目标服上的同类带参数输入透传给目标服，只有无参数的退出命令由 CP 接管。

| 命令 | 说明 |
|---|---|
| `cp status` | 当前配置模式；宿主实际监听地址与大厅内部监听地址分别标注；大厅会话数；目标服务器在途连接数；本次启动大厅处理器的非预期异常数（不含宿主/JVM 全部异常）；Geyser 桥注册状态。未启用大厅的项显示“未启用”，无法读取的值显示“不可用” |
| `cp list` | 当前仍连接在大厅的会话，按名字排序：名字、后端在线/离线设置（玩家 GUI 中的选择）、微软账号状态（未登录 / 登录中 / 已登录） |
| `cp links` | 已提交关联，显示为 `基岩玩家名(XUID: …) → Java玩家名(JavaUUID: …)`；名字未记录时显示“未知玩家名”并保留 ID，不输出任何账号凭据 |
| `cp info <玩家名>` | 按原始身份合并重复结果，每个身份显示名字与在线/离线状态、`JavaUUID` 或数字 `XUID`、书签数及带对方玩家名/ID 的关联。当前大厅会话优先于历史/已知名记录，已关联基岩玩家仍显示自己的 XUID。支持离线查询、忽略大小写、含空格基岩名；同名不同身份仍分别列出。未验证、未加载或不存在的档案显示“不可用”，查询不会创建档案文件 |
| `cp version` | 实际运行的插件版本与 ViaProxy 版本、桥协议版本；桥有效注册时显示桥自身与 Geyser 的运行版本（支持范围：ViaProxy 3.4.x 最低 3.4.13，桥接 Geyser 2.11.x 最低 2.11.3） |
| `cp debug on\|off` | 立即改变 ConnectPlus 诊断开关，仅本次运行有效，不写回 config.yml；官方默认 DEBUG 仅写 `logs/debug.log`，控制台没有 DEBUG 属于正常路由。开启时立即写一条调试记录；日志后端拦截 DEBUG 时明确提示，不修改宿主日志设置 |
| `cp accounts` | 本次升级后实际进入大厅的身份按当前关联去重后的玩家总数，并给出 Java/基岩原始身份数与合并数。绑定后将基岩身份并入对应 Java 身份计数，解绑后恢复分别计数；重复进出与切服返回不重复计数，仅登录微软账号不增加人数 |
| `cp help` | 列出全部命令、别名与参数 |

访问索引（`visits-index.json`）或关联索引损坏时，相关查询明确报告不可用，绝不把损坏数据当成“零”上报，也不会覆盖原文件。

`cp info` 的“在线”表示当前在大厅；“离线”表示没有当前大厅会话，也可能正在目标服务器游玩，不代表已退出整个代理。

## 相关文件

黑白名单文件为 `plugins/ConnectPlus/whitelist.json` 和 `blacklist.json`，格式及操作见下节。关联恢复的短期意图保存在 `players/.transactions/`，完成后删除；它不是绑定历史或账号凭据备份。

| 文件 | 说明 |
|---|---|
| `plugins/ConnectPlus/config.yml` | 插件配置（上表各项） |
| `plugins/ConnectPlus/languages/en.yml` | 英文文案（首次启动自动生成，可直接编辑覆盖内置值；删除某行 = 恢复内置） |
| `plugins/ConnectPlus/languages/zh.yml` | 中文文案（同上） |
| `plugins/ConnectPlus/languages/<自定义>.yml` | 自定义语言包：复制 en.yml 翻译后放这里，并在 `language` 填文件名（不含 .yml） |
| `plugins/ConnectPlus/players/java/<JavaUUID>.json` | Java 档案及已关联的基岩玩家共享数据（书签、设置、按保存选项加密的账号令牌） |
| `plugins/ConnectPlus/players/bedrock/<XUID>.json` | 未绑定基岩玩家的独立档案，首次验证进入大厅时创建 |
| `plugins/ConnectPlus/players/identity-links.json` | XUID 与 Java UUID 的一对一关联索引，关联成功后写入 |
| `plugins/ConnectPlus/visits-index.json` | 访问与名字索引（本次升级后开始记录）：实际进入大厅的原始身份、最近名字与协议 UUID，以及已知名 Java 名；供 `cp info`/`cp accounts` 使用 |

## 黑白名单

黑白名单覆盖大厅登录、从大厅转服、通配直连和 `proxy` 模式。配置默认均为 `false`；开启后的规则变化立即重新检查在线连接，不符合规则时断开与代理的连接。黑名单优先于白名单。名单匹配入口 Java UUID 或基岩 XUID，名字只用于查询/显示，成员资格不等于正版认证、也不授予账号或档案权限。

命令只在代理控制台提供。根 `cp` / `connectplus`（包括 `/cp` / `/connectplus`）、白名单 `whitelist` / `wl`、黑名单 `blacklist` / `bl` 均等价。

| 示例 | 行为 |
| --- | --- |
| `cp wl` / `cp wl help` | 帮助及黑白名单运行开关 |
| `cp wl on` / `cp wl off` | 只改运行开关，重启恢复 config 值 |
| `cp bl add java <玩家名或UUID>` | 将唯一 Java 起点及当前绑定方加入黑名单 |
| `cp bl remove bedrock <玩家名或XUID>` | 将唯一基岩起点及当前绑定方移出黑名单 |
| `cp wl list` / `cp bl list` | 开关关闭也能查看名字、平台和主标识 |
| `cp wl reload` / `cp bl reload` | 原样读取对应 JSON，不读 config、不改运行开关、不写回、不联动绑定方 |
| `cp access check <玩家名或UUID/XUID>` | 只读查询名单判断及原因，不断开、不修改文件；不测试桥可用性 |
| `cp info <玩家名>` | 查询侧在上，绑定侧在下，分别显示“是否在白名单：是/否/不可用”“是否在黑名单：是/否/不可用”；关闭开关也显示真实成员状态 |
| `cp status` | 每张名单以四行显示配置开关、当前状态和账号数，子项缩进四个空格；数据不可用时账号数显示“不可用”（绑定双方算两条） |

两张名单均支持 `help|on|off|add|remove|list|reload`。增删必须指定 `java` / `bedrock`；名字忽略大小写，支持带空格的基岩名。同名多个账号只列候选，不执行增删，请改用准确标识。未知玩家可以用规范 UUID/XUID 预添加；查询不会创建玩家档案。直连 Java 名字保存为元数据，不增加大厅访问人数，也不升级认证状态。

`cp help` 会列出 `cp wl` / `cp bl` 和完整别名、平台参数及 `access check`。名单指令的帮助、状态、列表、增删、重载、查询与失败提示使用 `language` 配置和现有语言包（`ConsoleAccess.*`）；`language: zh` 使用中文，英文配置保留英文。控制台没有客户端 locale，`auto` 按现有规则回退英文；命令名及 `on/off` 保持原文。替换新版插件并重启后会补齐缺失语言项，保留原翻译。

`cp status` 黑白名单采用相同排版，例如：

```text
黑名单状态:
    配置文件: off,
    当前状态: off,
    黑名单账号数: 0
```

两份文件使用同一结构，字段大小写必须如下：

```json
{
  "schemaVersion": 1,
  "players": [
    {"name": "JavaPlayer", "clientType": "java", "UUID": "00000000-0000-4000-8000-000000000001"},
    {"name": "Bedrock Player", "clientType": "bedrock", "XUID": "2530000000000001"}
  ]
}
```

预添加时 `name` 可为空；空名单是 `"players": []`。UUID 使用完整带连字符格式；XUID 是无前导零、无符号 64 位范围内的正整数十进制字符串。允许辅助 UUID/XUID 字段，但基岩只匹配 XUID，不回退查 UUID。同平台主标识重复、结构/版本/标识不合法均加载失败。关闭开关初次启动可生成空文件；启用名单缺失或损坏时拒绝连接，修复后 `reload`。运行中重载失败保留上一份有效规则，原文件不被覆盖；手工修改后必须先重载，避免指令用旧快照覆盖外部编辑。

| 动作 | 白名单 | 黑名单 |
| --- | --- | --- |
| 指令 `add/remove` | 同步当前绑定双方、一次提交 | 同步当前绑定双方、一次提交 |
| 新绑定 | 不继承 | 即使关闭开关也继承另一方已有黑名单 |
| 解绑 | 保留记录，停止后续同步 | 保留记录，停止后续同步 |
| 手工编辑后 `reload` | 按文件原样，不补绑定方 | 按文件原样，不补绑定方 |

执行 `add` 时，起点与当前绑定方都会保存已知名字，包括离线玩家在访问/名字索引中的名字。旧记录缺少 `name` 时，再次执行同一条 `add` 即可补齐；已有名字和 UUID/XUID 保留。未知名字不凭空填写，`reload` 和事务恢复不补写已有记录的名字。增删成功提示注明名单：英文如 `Added JavaPlayer (...) to whitelist.`，中文如“已将 JavaPlayer (...) 添加到白名单”。升级会补充新的 `ConsoleAccess.AddedToList` / `RemovedFromList` 语言项，旧成功提示项保留但不再用于这两条提示。

即使操作起点没有名单记录，`remove` 也移除当前绑定方。关联索引损坏时增删报告错误，不能静默只改起点；proxy 模式同样读取已保存的关联。黑名单数据不可用时不能安全计算新绑定继承，需先修复并重载，即使其开关关闭。

关联已经提交而继承失败时显示“关联成功。名单同步尚未完成”，不会伪装成完全成功或撤回已提交关联。短期事务资料保留，受影响主键在黑名单开启时拒绝，账号/档案租约与转服操作暂停。修复文件后**重启**以执行事务恢复；普通 `reload` 不重放事务。恢复失败继续保持待恢复状态；成功重放且旧档案清理完成后才清除。切换到 proxy 模式启动也会恢复此前留下的事务。

基岩平台已确认但缺 XUID 时：白名单关闭放行（只开黑名单也放行，并记录检查跳过限制），白名单开启拒绝。平台未知不是“已确认基岩缺 XUID”：任一名单开启时拒绝，不能用临时 wire UUID 冒充 Java。无 Geyser 的官方宿主可按公开插件信息确认离线 Java；混合宿主上未经认证且桥未能分类的 Java 也可能被拒绝，请使用完成正版认证的 Java 入口及健康桥接。名单与受保护账号资格仍分别检查。

Java 同步拒绝会关闭原前后端通道，避免宿主在事件返回后继续发送登录包。官方接口不能暂停异步基岩解析期间的原生转发，因此基岩仍可能短暂进入目标服，再被负面结果断开。官方重复 XUID 策略保持“原客户端继续连接、重复客户端被拒绝”，不改宿主认证或重复登录规则。

名单已经判定放行的连接，普通连接/转服不再额外要求主标识。两份名单都关闭时，平台未知不会新增普通操作限制；账号与受保护档案仍独立执行既有认证和租约检查。身份解析尚待完成或已终态拒绝时，不能提前转服。

内置语言升级只补缺失文本并保留原翻译/注释；损坏文件不覆盖。流式 YAML 根或显式文档结束符不适合安全追加时，保留文件并由运行时内置值补缺失项。登录前尚无 locale 时，`auto` 使用英文。黑名单拒绝有 `[BLACKLIST]` 标记，官方控制台 ERROR 颜色由宿主原生日志实现；真人目视验收另行记录。

自动检查记录与真人验收清单分开保存。解绑不追溯旧绑定、缺 XUID 的黑名单覆盖限制、标识不等于认证，以及手工文件可能使双方名单不同步，均需运营者按实际需求理解。

## 常见问题

- **GUI 物品名后面出现 `#4101` 之类的数字？** 那是 Minecraft 客户端 F3+H「高级提示框」的调试信息，不是插件发送的；按 **F3 + H** 关闭即可。
- **改了语言没生效？** 修改 `language` 或语言文件后请完整重启代理；游戏内文案以 `languages/*.yml` 与内置包合并后的结果为准。使用 `auto` 时，更改客户端语言后重新连接。

## Velocity / BungeeCord 目标的自动版本识别

Velocity 和 BungeeCord 的本地状态响应可能回显查询客户端的版本，无法据此判断后端版本。CP 在自动探测返回值等于客户端版本时，增加一次使用未知协议的状态查询；该代理会改为报告自身支持的最高版本。额外查询失败或返回未知版本时，保留第一次有效结果；手动指定版本直接使用选定值。多后端代理的状态信息无法保证每台后端的实际版本，后端与代理报告版本不同的目标仍应手动指定。
