# ConnectPlus

[English](README.md) | [简体中文](README.zh-CN.md)

本项目的灵感与部分代码来自 [MiniConnect](https://github.com/ViaVersionAddons/MiniConnect)。

**一个入口，收藏常玩的服务器，在游戏内选择并切换。**

ConnectPlus 是 [ViaProxy](https://github.com/ViaVersion/ViaProxy) 的插件。玩家进入内置大厅后，可以通过菜单填写 Minecraft Java 服务器地址、选择版本、管理个人书签、登录微软账号，并在目标服务器与大厅之间切换，无需每次退回多人游戏列表重新连接。

同一台代理可以供多名玩家使用，每个人分别选择自己的目标服务器。安装官方 Geyser-ViaProxy 和独立的 ConnectPlus-GeyserBridge 扩展后，基岩版玩家也可以使用大厅，并将基岩账号关联到自己的 Java 档案。

本文面向玩家与部署管理员，按 **ConnectPlus 1.0.0（预发布）** 的实现编写。文中的端口是部署示例，实际连接地址以管理员的配置为准。

**已有代理入口的玩家**可以直接阅读[玩家使用指南](#玩家使用指南)：连接管理员提供的地址 → 在菜单里设置目标地址 → 按需登录微软账号 → 点击连接。换服时输入 `/dc` 回大厅，再选另一台服务器。

## 功能与适用场景

| 功能 | 使用者可以做什么 |
| --- | --- |
| 内置大厅 | 连接代理后直接打开菜单，在游戏内完成连接设置，无需额外搭建大厅服务端 |
| 多人共享代理 | 每位玩家独立选择目标服务器，分别保存书签和个人设置；同一网络下的玩家按各自身份管理数据 |
| 跨版本连接 | 借助 ViaProxy 的协议转换连接不同版本的 Java 服务器；可以自动检测目标版本，也可以手动指定 |
| 游戏内切服 | 保留客户端与代理的连接，进入目标服务器、返回大厅，再选择其他服务器 |
| 个人书签 | 保存服务器地址与版本，查看详情、重命名、修改地址或版本、确认删除 |
| 微软账号登录 | 通过浏览器设备码授权，为需要正版验证的目标服务器提供账号认证 |
| 保存登录信息 | 自己决定是否在代理上保存登录；关闭保存后，登录仅在本次代理连接期间有效 |
| 个人离线模式 | 保留大厅中的微软登录，同时选择用离线身份连接目标服务器 |
| 连接恢复 | 目标服务器意外断开时返回大厅，或按管理员设置自动重连；被踢时可返回大厅并显示原因 |
| 服务器转移处理 | 目标服务器请求转移到其他地址时，按配置确认、直接跟随或忽略 |
| 中文与英文界面 | 内置两种语言，支持按玩家客户端语言选择，也支持管理员自定义文案 |
| 基岩身份与关联 | 安装桥接后，按 Xbox 身份保存独立档案，或关联 Java 档案，共享书签和设置 |
| 控制台管理 | 查看大厅会话、账号关联、玩家资料、累计访问人数、版本和桥接状态，临时开启诊断日志 |

适合搭建一个供自己、朋友或多个玩家使用的跨版本连接入口。ConnectPlus 的大厅用于选择和管理连接；实际游戏世界、背包、权限、白名单及游戏进度仍由目标服务器管理。

## 版本与运行要求

| 组件 | 当前要求 |
| --- | --- |
| ConnectPlus | 当前版本为 `1.0.0`（预发布） |
| Java 运行环境 | 仅 Java 入口使用 ConnectPlus 至少需要 Java 17；安装基岩桥接需要 Java 21 或更高版本。统一部署可使用 Java 21，并同时满足宿主自身要求 |
| ViaProxy | 使用未修改的官方版本，插件最低要求 `3.4.13`；基岩桥接支持 `3.4.x` 系列且不低于 `3.4.13` |
| Geyser-ViaProxy（基岩接入时） | 使用未修改的官方 `2.11.x`，最低 `2.11.3` |
| ConnectPlus-GeyserBridge（基岩身份功能） | 与 ConnectPlus 桥接协议匹配的独立扩展，当前版本为 `1.0.1` |
| Java 客户端 | 当前切服逻辑覆盖 Java 正式版 `1.7.2` 至 `26.3`；实际入口还须受到所用 ViaProxy 的支持 |
| 基岩客户端 | 使用所安装 Geyser 构建支持的基岩版本，并登录 Xbox 账号 |
| 网络 | 代理需要能访问目标服务器；账号登录还需要能访问微软、Xbox 和 Minecraft 的认证服务 |

ConnectPlus、Geyser-ViaProxy 和桥接扩展运行在**同一个 ViaProxy 实例**中。桥接扩展当前适用于 Geyser-ViaProxy 部署方式。

新版宿主或客户端是否可用，需同时看宿主支持范围和插件适配情况。遇到尚未适配的客户端协议时，ConnectPlus 会拒绝启动切服并提示更新。

## 安装与首次启动

### 1. 准备运行目录

从 [ViaProxy 官方发布页](https://github.com/ViaVersion/ViaProxy/releases) 获取官方 JAR，放入一个独立文件夹。为了方便填写命令，以下将宿主文件重命名为 `viaproxy.jar`。

将获取到的 ConnectPlus 安装包重命名为 `ConnectPlus.jar`，放入 `plugins/`。下文示例统一使用不带版本后缀的文件名：

```text
ViaProxy/
├── viaproxy.jar
└── plugins/
    └── ConnectPlus.jar
```

所有命令都在这个 `ViaProxy/` 文件夹中执行，后文的配置路径也相对于它。不要把 ConnectPlus 放到目标服的 Bukkit/Paper 插件目录，或客户端的 `mods/` 目录。

### 2. 生成配置

先确认终端中的 Java 版本：

```shell
java -version
```

首次启动并生成宿主配置：

```shell
java -jar viaproxy.jar config viaproxy.yml
```

这是 ViaProxy 的官方配置启动方式；配置文件首次创建后，宿主会提示编辑配置并退出。ConnectPlus 加载时会生成 `plugins/ConnectPlus/config.yml` 和默认语言文件。宿主启动方式也可参考 [ViaProxy 官方使用说明](https://github.com/ViaVersion/ViaProxy#usage-for-server-owners-config)。

如果进程仍在运行，先在代理控制台输入 `stop`，等待退出后再编辑配置。

### 3. 配置 Java 入口

编辑运行目录中的 **`viaproxy.yml`**，修改已有同名字段：

```yaml
bind-address: 0.0.0.0:25565

# 大厅会接管普通连接；这里只是宿主要求保留的默认目标字段。
# 若之后使用普通代理模式，请改为真实目标服务器。
target-address: 127.0.0.1:1
target-version: 1.21.4

# Java 玩家要使用 ConnectPlus 的微软账号功能，入口须完成正版验证。
proxy-online-mode: true

# 玩家在 ConnectPlus 大厅中分别登录账号。
auth-method: NONE

# 普通地址进入大厅；通配符直连按需另行配置。
wildcard-domain-handling: NONE
```

编辑 **`plugins/ConnectPlus/config.yml`**，修改对应字段：

```yaml
mode: lobby
language: zh
motd: "§bConnectPlus 大厅\n§7选择服务器，开始游戏"
allowAccountLogin: true
blockLocalTargets: true

geyser-support:
  enabled: false
```

这些片段仅列出需要关注的字段，**请修改生成配置里的对应值，保留其他设置，避免重复添加同名字段**。

如果只想让未通过 Java 正版认证的客户端进入大厅，可将宿主的 `proxy-online-mode` 设为 `false`，但这些 Java 连接不能使用 ConnectPlus 的微软账号功能。入口认证与目标服务器认证的区别见[微软账号与登录保存](#微软账号与登录保存)。

### 4. 启动并确认

```shell
java -jar viaproxy.jar cli
```

每次启动都应从同一个运行目录执行。也可以运行 `java -jar viaproxy.jar` 打开 ViaProxy 图形界面，并在界面中启动代理；请确认界面的在线模式与监听配置符合上述设置。

正常启动后，可在代理控制台执行：

```text
cp version
cp status
```

确认 ConnectPlus 已加载、模式为 `lobby`，并查看**宿主实际监听地址**。日志中的 `Lobby server listening on 127.0.0.1:...` 是内部大厅地址，由插件自动分配，玩家应连接 ViaProxy 的对外入口。

### 5. 让玩家连接

按本节示例，Java 玩家在多人游戏列表中添加：

```text
代理所在机器的地址:25565
```

同机测试可用 `127.0.0.1:25565`；局域网玩家使用代理机器的局域网地址，公网玩家使用域名或公网地址。

公网部署需要在防火墙、安全组和路由器/隧道中放行或映射 **TCP 25565**。`0.0.0.0` 是监听配置，不是让玩家填写的服务器地址。其他监听端口请同步替换。

进入后应看到大厅主菜单。只使用 Java 入口时，安装到这里即可；需要基岩接入时继续下一节。

## 基岩版接入

桥接扩展项目仓库：[ConnectPlus-GeyserBridge](https://github.com/Kongtu5i/ConnectPlus-GeryserBridge)。扩展的获取方式、安装与版本说明可在该仓库查看。

### 1. 安装 Geyser 与桥接扩展

从 [Geyser 官方下载页](https://geysermc.org/download/) 获取支持范围内的 **Geyser-ViaProxy** 构建，放入 ViaProxy 的 `plugins/`。启动一次生成配置，然后关闭代理。

将获取到的桥接扩展 JAR 重命名为 `connectplus-geyserbridge.jar`，放入 **`plugins/Geyser/extensions/`**，目录不存在时手动创建。Geyser 插件与 Geyser 扩展的目录不同，扩展安装规则见 [Geyser 官方说明](https://geysermc.org/wiki/geyser/extensions/#installing-extensions)。

```text
ViaProxy/
├── viaproxy.jar
└── plugins/
    ├── ConnectPlus.jar
    ├── Geyser-ViaProxy.jar
    ├── ConnectPlus/
    │   └── config.yml
    └── Geyser/
        ├── config.yml
        └── extensions/
            └── connectplus-geyserbridge.jar
```

### 2. 开启 ConnectPlus 基岩支持

修改 `plugins/ConnectPlus/config.yml` 中的对应字段：

```yaml
mode: lobby
allowAccountLogin: true

geyser-support:
  enabled: true
```

开启 `geyser-support.enabled` 只是允许可信桥接接入，并不会自动把 `allowAccountLogin` 改为 `true`。

### 3. 设置 Geyser

修改 `plugins/Geyser/config.yml` 中的对应字段：

```yaml
bedrock:
  address: 0.0.0.0
  port: 19132

java:
  auth-type: offline

advanced:
  bedrock:
    validate-bedrock-login: true
    use-waterdogpe-forwarding: false
```

这里的 `offline` 是 Java 下游认证配置，不会取消基岩玩家的 Xbox 身份验证；须保持 `validate-bedrock-login: true`。当前桥接不支持 Floodgate 认证模式或 WaterdogPE 身份转发。

Geyser-ViaProxy 的实际 Java 认证方式由 ViaProxy 管理，玩家进入大厅后通过 ConnectPlus 分别登录 Java 账号。本节是 ConnectPlus 桥接的部署方式；一般 Geyser 安装、网络和端口设置可参考 [Geyser-ViaProxy 官方安装说明](https://geysermc.org/wiki/geyser/setup/self/viaproxy/)。

如果配置里有 `clone-remote-port`，请确认它是否会覆盖手动填写的基岩端口；需要固定使用 `19132` 时应关闭端口跟随。

### 4. 重启并检查桥接

使用 Java 21 或更高版本重新启动 ViaProxy。在日志中查找：

```text
registered with ConnectPlus (bridge capabilities:
```

并执行 `cp status`、`cp version`，确认桥接注册状态及实际运行版本。首次启动 Geyser 时，还需等待 Minecraft 素材下载、提取和加载完成。

基岩身份确认在后台进行。如果菜单先打开、档案或账号状态稍后更新，请等待确认完成后再操作。桥接缺失、失效或不兼容时，普通连接仍可使用，但不能读取受保护的基岩档案、恢复保存账号或关联账号。

### 5. 基岩玩家连接

在基岩客户端登录 Xbox 账号后，添加服务器：

| 字段 | 按本节示例填写 |
| --- | --- |
| 名称 | 任意名称，例如 `ConnectPlus` |
| 地址 | 代理机器的域名、局域网地址或公网地址 |
| 端口 | `19132`，以 Geyser 实际监听配置为准 |

基岩入口使用 **UDP**。公网部署须放行/映射 **UDP 19132**；只开放 Java 的 TCP 端口无法让基岩客户端接入。Java 玩家仍连接 Java TCP 入口。

## 玩家使用指南

### 大厅菜单与快捷栏

普通入口连接成功后会自动打开主菜单。关闭箱子菜单后，快捷栏会出现：

| 快捷栏位置 | 物品 | 操作 |
| --- | --- | --- |
| 第 5 格 | 指南针 | 打开大厅主菜单 |
| 第 9 格 | 屏障 | 断开与代理的连接 |

选中物品后使用它：Java 可右键使用或左键挥动，基岩可使用或触屏点击。进入或返回大厅时默认选中第 5 格。基岩玩家请先关闭聊天框，再使用指南针。

箱子菜单打开时，两件快捷物品会暂时收起；关闭后恢复。它们的位置固定，移动、丢弃或交换后会被恢复。连接目标服务器前会清理大厅物品，回大厅时重新发放。

普通聊天不会打开菜单。只有菜单提示输入地址、书签名称等内容时，聊天输入才会用于对应操作。

主菜单的**使用说明**（书）提供游戏内教程；旧版客户端可能以书本界面显示，阅读结束后可用指南针重新打开菜单。

### 连接第一个服务器

1. 点击主菜单中的**设置服务器地址**（命名牌）。
2. 在聊天栏输入目标地址，例如 `play.example.com` 或 `play.example.com:25565`。未填端口时按 Java 服务器常用端口 `25565` 处理，无需添加 `http://` 或 `https://`。
3. 通常保持版本未设置，让插件自动检测。需要指定时，点击**设置协议版本**（铁砧），选择**目标服务器的版本**。
4. 如果目标服需要正版认证，先在菜单中完成微软账号登录，并确认个人离线模式已关闭。
5. 点击**连接到服务器**（木门），等待进入目标服务器。

自动检测适用于支持现代服务器列表查询的 `1.7+` 目标。状态查询被拦截、探测不准确或需要连接更早版本时，可手动选择目标版本。目标版本与自己的客户端版本可以不同。

地址输入和书签地址编辑支持将全角英文字母、数字和标点转换为半角，例如 `１２３．４５．６７．８９：２５５６５` 会转换为 `123.45.67.89:25565`，中文域名保留。转换后仍须通过管理员设置的地址限制。

主菜单的地址输入期间，发送以 `/` 开头的内容可取消本次地址输入并返回菜单；其他编辑项请按当前聊天提示操作。

### 代理目标的自动版本识别

Velocity 和 BungeeCord 的本地状态响应可能回显查询客户端的版本，无法据此判断后端版本。CP 在自动探测返回值等于客户端版本时，增加一次使用未知协议的状态查询；该代理会改为报告自身支持的最高版本。额外查询失败或返回未知版本时，保留第一次有效结果；手动指定版本直接使用选定值。多后端代理的状态信息无法保证每台后端的实际版本，后端与代理报告版本不同的目标仍应手动指定。

### 返回大厅、换服与退出

在通过 ConnectPlus 进入的目标服务器中，输入：

```text
/dc
```

或 `/disconnect`，即可返回大厅。随后使用菜单选择另一个地址或书签，再点击连接。

在**大厅中**输入同样的命令，会断开代理连接。主菜单和快捷栏的“断开连接”也用于退出代理。点击 Minecraft 自身的“断开连接”按钮同样会结束整个客户端连接；想换服时请先使用 `/dc` 返回大厅。

### 保存和管理书签

1. 在主菜单设置好服务器地址和目标版本。
2. 打开**书签**（末影箱）。
3. 点击**保存当前服务器**，将当前地址与版本保存为个人书签，初始名称使用服务器地址。
4. 在列表中左键点击/点选书签，进入详情页。
5. 按需重命名、修改地址、重新选择版本，或点击详情中的**连接到服务器**。

点击列表中的书签只会打开详情。删除需要在详情页点击删除，并在确认页再次确认；取消则保留书签。选择版本后会保存到该书签并返回详情，使用返回按钮或关闭选择页可以取消本次版本选择。

默认每个玩家最多保存 **50** 个书签，超过一页后可翻页。保存同名书签会更新对应记录；重命名时不能与另一个已有书签重名。书签保存在代理上，重新连接后可继续使用。

### Java 与基岩菜单差异

Java 客户端使用各页自己的标题和行数。已验证的基岩连接统一使用标题为 **ConnectPlus** 的六行箱子菜单，底行第 3 格的纸张显示当前页面名称。

基岩玩家使用页面内的**返回按钮**回到上一级；直接关闭箱子会退出整个菜单并恢复指南针。Java 的子页面通常在关闭后返回上一级。已关联 Java 档案的基岩玩家仍使用基岩菜单呈现方式。

### 目标服断线、被踢或请求转移

默认情况下，目标服意外断开或踢出玩家时，ConnectPlus 会尝试送回大厅，并显示连接失败或踢出原因。管理员也可以启用自动重连，或将被踢策略改为直接断开。

目标服发送服务器转移请求时，默认先回大厅显示确认菜单；确认后连接新地址，取消则留在大厅。若管理员改为 `follow` 会直接跟随转移，`ignore` 则忽略请求。

切服和恢复需要等待目标服务器响应。超时、网络不可达、身份验证失败或协议不支持时，玩家会收到相应提示；代理进程退出或客户端自身断网仍会结束连接。

## 微软账号与登录保存

### 两次认证分别解决什么问题

| 认证 | 用途 |
| --- | --- |
| 连接代理时的身份认证 | 确认谁在使用大厅档案。Java 依赖 ViaProxy 在线模式和实际正版验证；基岩依赖 Xbox 验证与可信桥接 |
| 大厅中的微软账号登录 | 为连接正版 Java 目标服务器提供该玩家的账号凭据 |

**Java 玩家即使已经通过正版客户端进入大厅，连接需要正版认证的目标服前，仍需在大厅菜单里登录微软账号。** 基岩版的 Xbox 登录本身也不能替代 Java 目标服要求的账号授权；所登录的微软账号需要具备目标服要求的 Java 游戏资格。

账号功能须由管理员开启，并且当前连接的身份认证有效。Java 入口关闭在线模式时，未认证的 Java 玩家不能通过菜单使用该功能。基岩玩家在桥接有效且账号功能开启时，可以独立于 Java 入口的在线模式使用账号登录与关联。

### 登录步骤

1. 点击主菜单中的**使用微软账号登录**。
2. 菜单关闭，聊天栏会显示授权网址与一次性设备码。
3. 在浏览器打开聊天提示的网址，输入设备码并登录自己的微软账号。
4. 完成网页授权，保持游戏连接，等待大厅提示登录成功。
5. 菜单会重新打开，账号项显示已登录的账号名，再连接目标服务器。

较新 Java 客户端（`1.21.5+`）点击网址会复制链接，旧版点击会尝试打开浏览器；无法点击时可以手动复制网址与设备码。以实际聊天提示为准。

密码在微软的网页中输入，ConnectPlus 不保存微软密码。授权成功后，插件按你的保存选项处理登录令牌。设备码过期、授权取消或网络请求失败时，可以重新发起登录。基岩玩家首次登录 Java 账号还会执行关联，请先阅读[账号关联说明](#java-与基岩账号关联)。

### 保存登录信息

主菜单的**保存登录信息**（拉杆）默认开启：

| 设置 | 效果 |
| --- | --- |
| 开启 | 在代理上加密保存登录信息，后续进入大厅可恢复登录；凭据失效时仍需重新授权 |
| 关闭 | 立即移除当前档案中已保存的账号凭据，当前连接中的登录仍可使用；退出代理后需重新登录 |

返回大厅和切换目标服务器仍属于同一次代理连接。关闭保存并不会立即注销，也不会删除书签；重新开启保存时，当前可用登录可以再次保存。

书签、设置和保存的账号数据位于**代理服务器**。令牌使用 AES-GCM 加密，密钥保存在同一代理的 `secret.key` 中。管理员需要妥善保管数据目录，玩家应在自己信任的代理上授权账号。

### 离线模式、注销和删除有什么区别

| 操作 | 影响 |
| --- | --- |
| 开启个人**离线模式**（红石火把） | 连接后端时使用原始玩家名及其离线 UUID，不发送微软账号凭据；大厅登录和书签保留。该选择也用于书签连接、重连及跟随服务器转移 |
| 关闭个人离线模式 | 有可用且允许使用的微软登录时，连接后端使用该账号；没有账号时不会自动取得正版身份 |
| 点击已登录的账号项**注销** | 移除当前登录及该档案中保存的账号凭据，书签保留 |
| 关闭**保存登录信息** | 当前连接中继续使用登录，退出代理后不再恢复 |
| **删除所有信息**（TNT）并确认 | 清除当前玩家资料中的账号、书签和设置，当前会话恢复初始状态；操作不可撤销 |

离线模式不能绕过目标服的正版验证。目标服按 UUID 区分存档时，切换在线/离线身份或后端账号可能使用不同的背包与游戏进度，这是目标服的身份规则。

“删除所有信息”用于清理玩家资料；**解除 Java/基岩关联请使用专门的解绑入口**。操作共享的 Java 档案前，应留意其中的数据也供已关联身份使用。

## Java 与基岩账号关联

本节适用于已经安装桥接、基岩身份验证成功且管理员允许账号操作的部署。

### 关联前的独立档案

未关联的基岩玩家按自己的 Xbox XUID 使用独立档案，保存自己的书签和设置；首次身份验证成功并进入大厅时，即会创建这份档案。

Java 玩家按经过认证的原始 Java UUID 使用自己的档案。同一个 Java 玩家使用不同客户端版本连接时，读取同一份档案；在大厅中更换用于目标服认证的账号不会改变原始 Java 档案的归属。

### 关联到 Java 账号

未关联的基岩玩家在主菜单点击微软账号登录后，会先看到数据变更提示，再进入设备码授权流程。授权和关联成功后：

- 当前基岩身份关联到授权确认的 Java UUID，关联关系是一对一。
- 开始使用对应 Java 档案；已有 Java 档案时读取其书签和设置，没有则创建。
- 原来的独立基岩档案会被清理，**基岩书签不会自动合并到 Java 档案**。有需要的地址请提前记录或请管理员备份。
- 此后从 Java 入口与该基岩入口进入时，都使用这份 Java 档案。

已经被其他账号关联的 XUID 或 Java UUID 会导致冲突，需要先解除已有绑定。授权取消或未提交的关联失败不会替换原来的基岩档案；请以大厅显示的结果为准。

### 解除关联

已关联的基岩玩家会在主菜单看到**解除与 Java 账号……的绑定**（锁链）入口。成功解绑后：

- 当前基岩连接不再使用 Java 账号凭据，改用新建的空白独立基岩档案。
- 原 Java 档案中的书签与保存登录信息继续保留，Java 玩家仍可使用。
- 已在关联时清理的旧基岩书签不会因解绑而自动恢复。

注销微软登录与解除关联是两个独立操作，注销不会代替解绑。

### 同一档案与重复登录

Java 和已关联的基岩身份对同一份受保护档案不能同时使用。新的已验证连接接管时，ConnectPlus 会协调旧会话退出，避免两边同时写入书签和账号数据；旧状态无法安全保存等情况下，接管可能失败。

**两个基岩客户端使用同一个 Xbox 账号**属于官方 Geyser 的重复 XUID 登录：原客户端保持在线，新连接被官方 Geyser 拒绝。ConnectPlus 桥接保持这项原生规则。

## 指令说明

### 玩家指令

ConnectPlus 当前只提供以下两种写法，均不带参数：

| 指令 | 在大厅中 | 在通过 ConnectPlus 切入的目标服务器中 |
| --- | --- | --- |
| `/disconnect` | 断开与代理的连接 | 返回大厅 |
| `/dc` | 同上，简短别名 | 同上，简短别名 |

想换服：在目标服务器输入 `/dc` → 返回大厅 → 通过菜单连接另一台服务器。

### 管理员控制台指令

以下指令在**ViaProxy 控制台**输入，使用 `cp` 或 `connectplus` 作为根命令，两种插件模式都可使用。根命令也接受 `/cp`、`/connectplus` 写法；单独输入 `cp` 会显示帮助。

| 指令 | 说明 |
| --- | --- |
| `cp help` | 列出支持的指令、别名与参数 |
| `cp status` | 查看配置模式、宿主实际监听地址、内部大厅地址、大厅会话数、正在进行的目标连接数、本次运行的大厅非预期异常数、桥接注册状态；黑白名单分别以四行缩进块显示配置开关、运行开关和账号数 |
| `cp list` | 列出当前大厅会话、各自的后端在线/离线选择和微软登录状态；不是所有正在目标服游戏的玩家列表 |
| `cp info <玩家名>` | 查询当前大厅或历史记录中的原始 Java UUID/XUID、大厅在线状态、书签数量与关联；支持忽略大小写、离线查询和含空格的基岩名；查询侧与绑定侧分别显示白名单/黑名单成员资格，关闭开关也显示真实成员状态 |
| `cp links` | 列出已提交的基岩 → Java 关联，显示双方名字及身份 ID，不显示账号令牌 |
| `cp accounts` | 查看已记录的累计访客人数，按当前关联关系去重，并列出 Java/基岩身份数与合并数 |
| `cp version` | 查看实际运行的 ConnectPlus、ViaProxy 和桥接协议版本；桥接已注册时显示桥接与 Geyser 版本 |
| `cp debug on` | 临时开启本次运行的 ConnectPlus 诊断日志，不修改配置文件 |
| `cp debug off` | 临时关闭本次运行的 ConnectPlus 诊断日志，不修改配置文件 |
| `cp wl` / `cp bl` | 白名单/黑名单帮助及运行开关；完整别名 `whitelist` / `blacklist` 对所有操作有效 |
| `cp wl on\|off` / `cp bl on\|off` | 仅改变本次运行开关，重启恢复配置值 |
| `cp wl add\|remove java\|bedrock <玩家名或UUID/XUID>` | 增删唯一目标及当前绑定方；黑名单使用相同操作，必须指定平台 |
| `cp wl list` / `cp wl reload` | 列表或只读重载文件，不重写、不联动绑定；黑名单使用相同操作 |
| `cp access check <玩家名或UUID/XUID>` | 只读查询成员资格与规则，不授予认证或账号权限 |

示例：

```text
cp info Steve
cp info Bedrock Player
connectplus status
cp debug on
```

`cp info` 按身份整理结果，同名但不同身份的记录可以分别列出；查询不会创建玩家档案。`cp accounts` 统计实际进入过大厅的玩家，不是已登录的微软账号数，也不是当前在线人数；从访问索引引入后开始记录，不能补算升级之前未记录的访客。关联后合并人数，解绑后重新分别计数。

`cp info` 中的 `[在线]` 表示当前在大厅，`[离线]` 表示没有当前大厅会话；后者也可能正在目标服务器游玩，不能据此判断玩家已退出整个代理。

访问或关联索引损坏时，相应查询会报告“不可用”，不会当成零人，也不会覆盖原文件。`cp status` 的异常数只统计大厅处理器记录的非预期异常，不代表整个 JVM、ViaProxy 或 Geyser 的全部错误。

停止代理使用宿主的 `stop` 指令。ConnectPlus 当前没有 `cp reload`、控制台切服、踢人或修改关联的管理指令；修改持久配置后请完整重启代理。

### 黑白名单

黑白名单覆盖大厅登录、从大厅转服、通配直连和 `proxy` 模式。配置默认均为 `false`；开启后的规则变化立即重新检查在线连接，不符合规则时断开与代理的连接。黑名单优先于白名单。名单匹配入口 Java UUID 或基岩 XUID，名字只用于查询/显示，成员资格不等于正版认证、也不授予账号或档案权限。

命令只在代理控制台提供。根 `cp` / `connectplus`（包括 `/cp` / `/connectplus`）、白名单 `whitelist` / `wl`、黑名单 `blacklist` / `bl` 均等价。

| 示例 | 行为 |
| --- | --- |
| `cp wl` / `cp wl help` | 帮助及黑白名单运行开关 |
| `cp wl on` / `cp wl off` | 只改运行开关，重启恢复 config 值 |
| `cp bl add java <玩家名或UUID>` | 将唯一 Java 起点及当前绑定方加入黑名单 |
| `cp bl remove bedrock <玩家名或XUID>` | 将唯一基岩起点及当前绑定方移出黑名单 |
| `cp wl list` / `cp bl list` | 开关关闭也能查看名字、平台和主标识 |
| `cp wl reload` / `cp bl reload` | 原样读取对应 JSON，不读 config、不改运行开关、不写回、不联动绑定方 |
| `cp access check <玩家名或UUID/XUID>` | 只读查询名单判断及原因，不断开、不修改文件；不测试桥可用性 |
| `cp info <玩家名>` | 查询侧在上，绑定侧在下，分别显示“是否在白名单：是/否/不可用”“是否在黑名单：是/否/不可用”；关闭开关也显示真实成员状态 |
| `cp status` | 每张名单以四行显示配置开关、当前状态和账号数，子项缩进四个空格；数据不可用时账号数显示“不可用”（绑定双方算两条） |

两张名单均支持 `help|on|off|add|remove|list|reload`。增删必须指定 `java` / `bedrock`；名字忽略大小写，支持带空格的基岩名。同名多个账号只列候选，不执行增删，请改用准确标识。未知玩家可以用规范 UUID/XUID 预添加；查询不会创建玩家档案。直连 Java 名字保存为元数据，不增加大厅访问人数，也不升级认证状态。

`cp help` 会列出 `cp wl` / `cp bl` 和完整别名、平台参数及 `access check`。名单指令的帮助、状态、列表、增删、重载、查询与失败提示使用 `language` 配置和现有语言包（`ConsoleAccess.*`）；`language: zh` 使用中文，英文配置保留英文。控制台没有客户端 locale，`auto` 按现有规则回退英文；命令名及 `on/off` 保持原文。替换新版插件并重启后会补齐缺失语言项，保留原翻译。

`cp status` 黑白名单采用相同排版，例如：

```text
黑名单状态:
    配置文件: off,
    当前状态: off,
    黑名单账号数: 0
```

两份文件使用同一结构，字段大小写必须如下：

```json
{
  "schemaVersion": 1,
  "players": [
    {"name": "JavaPlayer", "clientType": "java", "UUID": "00000000-0000-4000-8000-000000000001"},
    {"name": "Bedrock Player", "clientType": "bedrock", "XUID": "2530000000000001"}
  ]
}
```

预添加时 `name` 可为空；空名单是 `"players": []`。UUID 使用完整带连字符格式；XUID 是无前导零、无符号 64 位范围内的正整数十进制字符串。允许辅助 UUID/XUID 字段，但基岩只匹配 XUID，不回退查 UUID。同平台主标识重复、结构/版本/标识不合法均加载失败。关闭开关初次启动可生成空文件；启用名单缺失或损坏时拒绝连接，修复后 `reload`。运行中重载失败保留上一份有效规则，原文件不被覆盖；手工修改后必须先重载，避免指令用旧快照覆盖外部编辑。

| 动作 | 白名单 | 黑名单 |
| --- | --- | --- |
| 指令 `add/remove` | 同步当前绑定双方、一次提交 | 同步当前绑定双方、一次提交 |
| 新绑定 | 不继承 | 即使关闭开关也继承另一方已有黑名单 |
| 解绑 | 保留记录，停止后续同步 | 保留记录，停止后续同步 |
| 手工编辑后 `reload` | 按文件原样，不补绑定方 | 按文件原样，不补绑定方 |

执行 `add` 时，起点与当前绑定方都会保存已知名字，包括离线玩家在访问/名字索引中的名字。旧记录缺少 `name` 时，再次执行同一条 `add` 即可补齐；已有名字和 UUID/XUID 保留。未知名字不凭空填写，`reload` 和事务恢复不补写已有记录的名字。增删成功提示注明名单：英文如 `Added JavaPlayer (...) to whitelist.`，中文如“已将 JavaPlayer (...) 添加到白名单”。升级会补充新的 `ConsoleAccess.AddedToList` / `RemovedFromList` 语言项，旧成功提示项保留但不再用于这两条提示。

即使操作起点没有名单记录，`remove` 也移除当前绑定方。关联索引损坏时增删报告错误，不能静默只改起点；proxy 模式同样读取已保存的关联。黑名单数据不可用时不能安全计算新绑定继承，需先修复并重载，即使其开关关闭。

关联已经提交而继承失败时显示“关联成功。名单同步尚未完成”，不会伪装成完全成功或撤回已提交关联。短期事务资料保留，受影响主键在黑名单开启时拒绝，账号/档案租约与转服操作暂停。修复文件后**重启**以执行事务恢复；普通 `reload` 不重放事务。恢复失败继续保持待恢复状态；成功重放且旧档案清理完成后才清除。切换到 proxy 模式启动也会恢复此前留下的事务。

基岩平台已确认但缺 XUID 时：白名单关闭放行（只开黑名单也放行，并记录检查跳过限制），白名单开启拒绝。平台未知不是“已确认基岩缺 XUID”：任一名单开启时拒绝，不能用临时 wire UUID 冒充 Java。无 Geyser 的官方宿主可按公开插件信息确认离线 Java；混合宿主上未经认证且桥未能分类的 Java 也可能被拒绝，请使用完成正版认证的 Java 入口及健康桥接。名单与受保护账号资格仍分别检查。

Java 同步拒绝会关闭原前后端通道，避免宿主在事件返回后继续发送登录包。官方接口不能暂停异步基岩解析期间的原生转发，因此基岩仍可能短暂进入目标服，再被负面结果断开。官方重复 XUID 策略保持“原客户端继续连接、重复客户端被拒绝”，不改宿主认证或重复登录规则。

名单已经判定放行的连接，普通连接/转服不再额外要求主标识。两份名单都关闭时，平台未知不会新增普通操作限制；账号与受保护档案仍独立执行既有认证和租约检查。身份解析尚待完成或已终态拒绝时，不能提前转服。

内置语言升级只补缺失文本并保留原翻译/注释；损坏文件不覆盖。流式 YAML 根或显式文档结束符不适合安全追加时，保留文件并由运行时内置值补缺失项。登录前尚无 locale 时，`auto` 使用英文。黑名单拒绝有 `[BLACKLIST]` 标记，官方控制台 ERROR 颜色由宿主原生日志实现；真人目视验收另行记录。

自动检查记录与真人验收清单分开保存。解绑不追溯旧绑定、缺 XUID 的黑名单覆盖限制、标识不等于认证，以及手工文件可能使双方名单不同步，均需运营者按实际需求理解。

自动检查结果与真实客户端验收分别记录：自动验证、真实客户端清单。

## 管理员配置参考

ConnectPlus 配置文件位于 **`plugins/ConnectPlus/config.yml`**。宿主的 `viaproxy.yml` 和 Geyser 的配置分别管理各自行为，不要将不同文件的字段混写。

除 `cp debug on/off`、`cp wl on/off` 和 `cp bl on/off` 提供的运行切换外，配置与语言文件修改后都按**重启代理**应用。插件加载时可能重新生成配置注释，中文说明以本文和[配置中文对照](docs/config-zh.md)为参考。

### 大厅、语言与连接限制

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `mode` | `lobby` | `lobby`：普通地址进入内置大厅；`proxy`：关闭大厅路由，使用 ViaProxy 常规代理行为 |
| `motd` | `§bConnectPlus Lobby` | Java 多人游戏列表中的大厅描述，支持 `§` 颜色代码及双引号内的 `\n` 换行；直连和 `proxy` 模式沿用目标服状态 |
| `language` | `en` | `en` 英文、`zh` 中文、`auto` 按客户端语言选择，或自定义语言包文件名（不含 `.yml`） |
| `switchTimeoutSeconds` | `15` | 一次切服允许的最长时间，单位秒；超时尝试回到大厅 |
| `maxConnectAttemptsPerMinute` | `30` | 每位玩家每分钟的连接尝试上限，`0` 关闭限流；回大厅的兜底流程不受此限制 |
| `blockLocalTargets` | `true` | 阻止目标连接到代理主机自身、回环、内网等受限地址 |
| `whitelist` | `false` | 白名单启动开关；控制台 on/off 仅影响本次运行，重启恢复此值 |
| `blacklist` | `false` | 黑名单启动开关，命中时优先拒绝；控制台开关同样不写配置 |
| `maxBookmarksPerPlayer` | `50` | 每份玩家资料允许保存的书签数量上限 |

公网共享代理通常保留 `blockLocalTargets: true`。如果你的目标服就在同机或内网，默认会被拒绝；只有确实需要连接可信内部目标、并能控制代理使用者时，才考虑设为 `false`。关闭后，玩家指定的目标可以指向代理机器与内网服务，需要由部署者控制访问范围。

### 账号与基岩桥接

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `allowAccountLogin` | `true` | 管理员的账号总开关。开启后仍要求连接完成可信身份认证；关闭时不登录、恢复或使用保存账号，已有加密数据保留 |
| `accountLoginAllowlist` | `[]` | 允许发起微软账号登录的玩家名名单，忽略大小写；空列表允许所有满足认证条件的玩家发起登录。保持默认空列表即可，此配置项为 MiniConnect 遗留配置项，ConnectPlus 提供了重新设计、更好用的白名单功能 |
| `geyser-support.enabled` | `false` | 允许匹配的桥接扩展注册和提供可信基岩身份；仅打开此项不能代替安装扩展或通过 Xbox 验证 |


**自动关闭账号功能的规则：**如果 ViaProxy 的 `proxy-online-mode` 和 ConnectPlus 的 `geyser-support.enabled` 都关闭，ConnectPlus 会在代理加载/启动时将 `allowAccountLogin` 设为 `false` 并写回配置。之后重新开启任一认证路径，仍需管理员手动把 `allowAccountLogin` 改回 `true`。

关闭账号总开关会同时影响 Java 和基岩连接，正在完成的异步登录、切服、重连及转移也要遵守此限制。已有书签和保存的加密令牌会保留，限制生效期间不使用这些凭据。

### 故障恢复与服务器转移

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `backendDownPolicy` | `lobby` | 目标服意外断开时，`lobby` 返回大厅；`reconnect` 尝试自动重连 |
| `reconnectAttempts` | `3` | 自动重连次数上限，耗尽后返回大厅；`0` 不重试，仅在 `backendDownPolicy: reconnect` 时使用 |
| `reconnectDelaySeconds` | `5` | 自动重连的基础等待秒数，后续失败会线性增加等待时间；首次恢复可立即开始 |
| `kickPolicy` | `lobby` | 被目标服踢出时，`lobby` 带原因返回大厅；`disconnect` 转发踢出并结束连接 |
| `transferPolicy` | `confirm` | 目标服要求转移地址时，`confirm` 返回大厅确认、`follow` 自动跟随、`ignore` 忽略 |

例如，希望目标服临时断开时尝试重连，修改已有字段：

```yaml
backendDownPolicy: reconnect
reconnectAttempts: 3
reconnectDelaySeconds: 5
kickPolicy: lobby
transferPolicy: confirm
```

### 诊断日志

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `debug` | `false` | 是否输出 ConnectPlus 的 DEBUG 诊断；持久修改后重启，临时修改使用 `cp debug on/off` |

日常启动、连接结果和恢复信息仍会输出；警告与错误不受此开关限制。官方 ViaProxy 默认将详细诊断写入 **`logs/debug.log`**，控制台和 `logs/latest.log` 主要显示日常输出，因此开启调试后控制台没有 DEBUG 内容属于正常情况。

`cp debug on/off` 只影响本次进程，重启后恢复为配置中的 `debug`。该开关控制 ConnectPlus 的诊断，ViaProxy 和 Geyser 仍遵循各自的日志设置。

### 自定义界面语言

首次加载会生成：

```text
plugins/ConnectPlus/languages/en.yml
plugins/ConnectPlus/languages/zh.yml
```

可以直接编辑对应文案，重启后生效。删除或留空某个文案键时，回退到内置文本。添加其他语言时，复制 `en.yml` 为 `fr.yml` 等文件，翻译其内容，并设置 `language: fr`；自定义包缺少的键回退英文。

设为 `language: auto` 时，按每位玩家的客户端语言选择，例如 `zh_cn` 对应 `zh`，存在 `de.yml` 时 `de_de` 对应 `de`，没有匹配包时使用英文。玩家在游戏中更改语言后，重新连接大厅以应用语言选择。

旧版 `messages.yml` 在没有 `languages/en.yml` 时会迁移为英文语言文件。新安装请使用 `languages/` 目录。

### 常规代理模式与通配符直连

`mode: proxy` 关闭 ConnectPlus 大厅路由，入口连接使用 ViaProxy 配置中的固定目标地址和版本。因此示例中的占位目标 `127.0.0.1:1` 必须换成真实目标。

`mode: lobby` 时，ViaProxy 的通配符地址可保留直接连接行为，例如 `目标地址_端口_版本.viaproxy.代理域名`。使用该方式需要另行配置 ViaProxy 的通配符处理和 DNS，按[宿主官方说明](https://github.com/ViaVersion/ViaProxy)设置；大厅中的书签与连接菜单面向普通大厅入口。

## 数据备份与升级

### 重要文件

以下路径相对于 ViaProxy 的运行目录：

| 路径 | 用途 |
| --- | --- |
| `viaproxy.yml` | 宿主监听、默认目标和 Java 入口认证配置 |
| `plugins/ConnectPlus/config.yml` | ConnectPlus 设置 |
| `plugins/ConnectPlus/languages/` | 内置语言文件和管理员自定义文案 |
| `plugins/ConnectPlus/secret.key` | 账号令牌加密密钥，须和玩家数据一起备份 |
| `plugins/ConnectPlus/players/java/<JavaUUID>.json` | Java 玩家档案，以及已关联基岩身份共用的数据 |
| `plugins/ConnectPlus/players/bedrock/<XUID>.json` | 未关联基岩玩家的独立档案 |
| `plugins/ConnectPlus/players/identity-links.json` | 已提交的基岩 XUID 与 Java UUID 关联 |
| `plugins/ConnectPlus/players/.transactions/` | 关联/解绑操作的恢复记录，按需产生，备份时一并保留 |
| `plugins/ConnectPlus/visits-index.json` | 进入大厅的访问记录与名字索引，供控制台查询使用 |
| `plugins/ConnectPlus/whitelist.json` | 白名单账号记录，与开关独立保存 |
| `plugins/ConnectPlus/blacklist.json` | 黑名单账号记录，与开关独立保存 |
| `plugins/Geyser/config.yml` | 安装 Geyser 时的基岩入口和认证设置 |
| `logs/latest.log`、`logs/debug.log` | 运行日志及详细诊断 |

### 备份与迁移

先正常停止代理，再备份**整个 `plugins/ConnectPlus/` 目录**，同时保存宿主与 Geyser 配置。迁移到另一台机器时，将这些数据和配置一起迁移，并重新检查监听地址与端口映射。

不要只备份玩家 JSON 而丢失 `secret.key`；丢失或替换密钥后，旧账号令牌无法解密，玩家需要重新授权。书签不依赖这个密钥。

不要把数据目录、密钥或包含账号信息的备份公开上传。绑定索引和事务记录由插件维护，不建议运行中手动编辑。

### 更新插件

1. 停止 ViaProxy，备份数据与配置。
2. 将旧的 ConnectPlus JAR 移出 `plugins/`，放入新版 JAR，确保只保留一个版本。
3. 如同时更新桥接，替换 `plugins/Geyser/extensions/` 中对应扩展，保留配置与玩家数据。
4. 核对新版插件、官方 ViaProxy、Geyser 和 Java 的支持范围。
5. 启动后执行 `cp version`、`cp status`，再用实际客户端测试进入大厅、读取书签、进服和返回。

升级时如果旧配置无法合并，插件可能将其保存为 `config.yml.backup-时间戳` 并生成默认配置。发现相关日志后，请对照备份重新应用原设置，再重启。旧版玩家资料的归属无法确认或迁移发生冲突时，应保留原文件与备份，不要手动覆盖新档案。

升级官方宿主时继续使用官方原包；ConnectPlus 与桥接的更新不需要维护宿主补丁。

## 常见问题与排查

| 现象 | 检查与处理 |
| --- | --- |
| 完全连接不上 Java 入口 | 检查 ViaProxy 是否运行、`bind-address`、TCP 防火墙/安全组及端口映射；使用 `cp status` 确认宿主监听地址 |
| 进入后没有大厅菜单 | 检查插件是否加载、`mode: lobby`，以及是否使用了通配符直连地址；菜单被关闭时使用第 5 格指南针 |
| 基岩客户端连接不上 | 检查 Geyser 已启动、客户端版本受到支持、实际基岩端口与 UDP 放行/映射；不要把 Java TCP 端口当成基岩端口 |
| 同一 Windows 机器上的基岩客户端无法连接 | 除监听和 UDP 外，可检查 Windows 应用的本机回环限制，参考 [Geyser 官方指引](https://geysermc.org/wiki/geyser/setup/self/viaproxy/)中的 loopback fix |
| 日志出现 `ConnectPlus not found` | 确认 ConnectPlus JAR 在同一实例的 `plugins/`，且没有加载失败 |
| 桥接未注册或出现 `bridge disabled` | 检查扩展目录、Java 21、宿主版本系列、`geyser-support.enabled`、Xbox 验证及 Floodgate/WaterdogPE 设置；根据同一日志的原因处理 |
| 基岩书签没有保存或账号入口不可用 | 先用 `cp status` 检查桥接；身份确认成功前或桥接失效后不能访问受保护档案和账号功能 |
| 微软账号登录提示被禁用 | 检查 `allowAccountLogin`；Java 还需要入口在线模式并实际通过正版验证，基岩需要有效桥接。两条认证路径曾同时关闭时需手动重新开启账号总开关 |
| 提示不允许使用微软登录 | 检查 `accountLoginAllowlist` 是否包含当前原始玩家名；该名单忽略大小写 |
| 目标服务器要求正版账号 | 完成大厅微软登录，并关闭个人离线模式；确认该账号具备 Java 游戏资格且未过期 |
| 设备码授权后仍失败 | 保持游戏连接，查看聊天原因和认证服务连通性；设备码过期、取消授权或账号不具备资格时重新尝试 |
| 输入目标地址被判为无效 | 检查地址/端口格式、是否误带网址前缀，以及 `blockLocalTargets` 是否拦截了同机或内网地址 |
| 自动版本检测失败 | 确认目标服状态查询可访问，尝试手动选择目标服务器版本；检查是否选成了自己的客户端版本 |
| 切服提示版本不支持 | 更新到适配该客户端协议的 ConnectPlus，并核对宿主支持；也可用已支持的正式版客户端连接 |
| 切服超时或一直连接失败 | 检查目标地址可达性、版本、正版账号要求和目标服日志；按需开启调试查看同一时段的失败原因 |
| `/connect` 或 `/bookmarks` 无效 | 当前 ConnectPlus 已移除这些指令，请用大厅菜单；返回大厅使用无参数 `/dc` |
| 在目标服输入 `/dc` 后退出代理 | 确认连接经过 ConnectPlus 大厅的切服流程；常规代理模式及通配符直连不属于这个返回大厅流程 |
| 关闭基岩箱子后没有回到上一级 | 基岩关闭操作会退出整个 GUI；请用页面里的返回按钮导航，或用指南针重新打开 |
| 普通聊天不能重新打开菜单 | 这是当前行为，请用第 5 格指南针 |
| GUI 物品名出现 `#4101` 等数字 | Minecraft 高级提示框已开启；Java 客户端按 `F3 + H` 关闭 |
| 修改语言后没生效 | 检查 `language` 与实际语言文件，重启代理；`auto` 模式更改客户端语言后重新连接 |
| 开启调试后控制台没有 DEBUG | 官方默认把详细日志写入 `logs/debug.log`，检查该文件与开启命令的反馈 |
| 关联提示冲突 | 一个 XUID 或 Java UUID 已有其他关联；先通过对应身份解除原绑定，管理员可用 `cp links` 查询 |
| 第二台基岩客户端用同一账号被拒绝 | 官方 Geyser 原生限制；旧客户端保持在线，先退出旧连接再登录 |

### 提交问题时准备什么

复现前在代理控制台输入 `cp debug on`，完成操作后执行 `cp debug off`。记录以下信息供维护者定位：

- `cp version` 与 `cp status` 的输出、Java 运行版本。
- Java/基岩客户端版本、目标服务端类型与版本。
- 具体操作步骤、发生时间、聊天错误、预期行为与实际结果。
- 同一时段的 `logs/latest.log`、`logs/debug.log`；涉及目标服时附目标服日志。

分享前移除账号令牌、设备码、密钥、密码及不想公开的玩家身份和网络地址。无需发送 `secret.key` 或整个玩家数据目录。

## 使用范围与验收说明

ConnectPlus 使用未修改的官方 ViaProxy 和 Geyser-ViaProxy，通过插件和独立扩展提供功能。协议翻译能力来自宿主；需要客户端模组的服务端、自定义认证和协议、特殊资源包及未来新协议，并不因安装本插件就自动获得兼容。

游戏内切服保留客户端与代理之间的连接，每个新目标仍需完成连接与登录。保留连接不意味着把一个目标服的世界、背包或游戏状态迁移到另一个目标服。

项目的自动化检查覆盖切服与恢复、账号策略、档案与关联、GUI 和命令等行为。**自动测试通过、宿主成功启动、桥接成功注册或 UDP Ping 正常，不等同于真实客户端完成验收。** Java/基岩不同版本的进服、移动、连续切换、返回大厅及关联操作，应在所用部署组合中分别复测。

部分真实客户端场景仍未执行。自动检查与真实客户端验收分别记录，请按实际部署组合进行验证。

## 从源码获取安装包

已经拿到插件 JAR 的使用者可以跳过本节。如果获取的是源码，先安装 JDK 17 或更高版本，再在源码根目录使用项目自带的 Gradle Wrapper：

Windows PowerShell：

```powershell
.\gradlew.bat build
```

Linux/macOS：

```shell
./gradlew build
```

首次构建需要联网下载 Gradle 与依赖。成功后，在以下目录找到生成的插件 JAR：

```text
build/libs/
```

将生成的 JAR 重命名为 `ConnectPlus.jar`，放入 ViaProxy 的 `plugins/`，按前文安装步骤使用。基岩桥接是另一个工程的安装包，需要单独获取；无需修改或重新编译官方宿主。
